# Research methodology

## Scientific approach

The project follows a transparent, defensible workflow:

- define a measurable security hypothesis
- gather representative telemetry
- normalize fields and standardize event semantics
- summarize activity by host, user, and process
- compare against baselines and peer groups
- validate results with explicit assumptions
- record next steps and limitations

## Metrics to track

- event count by host
- severity distribution
- process risk profiles
- anomaly score magnitude
- false positive sensitivity

## Good experiment design

A strong research note should answer:

- what problem are we solving?
- what telemetry was used?
- what method was applied?
- what thresholds were chosen?
- how were results validated?
- what should be tested next?
